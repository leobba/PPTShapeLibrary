# PPTShapeLibrary 安装与分发说明

> 发布产物：`publish/`（ClickOnce 本体）与 `dist/`（完整分发包），均由

## 方式一（推荐）：带环境检测的安装器 `dist/`

```
dist\
  安装 PPTShapeLibrary.exe     ← 双击这个（环境检测 + 安装引导）
  App\                        ← 插件本体：PPTShapeLibrary.vsto + Application Files\（请勿单独移动/删改）
  离线安装包\说明.txt           ← 可选：放入官方离线包即可离线安装
  安装说明.txt
```

> 为什么是 `App\` 而不是 `setup.exe`：`setup.exe`（ClickOnce 引导程序）内烤入了**发布机上的绝对 URL**，
> 拷到别人机器/别的目录后不可用；而 `.vsto` 部署清单内是**相对路径**（`Application Files\…`），
> 安装源就是它所在目录 —— 所以安装器改为调用 `VSTOInstaller.exe /Install "<dist\App\PPTShapeLibrary.vsto>"`，
> 分发到任何位置都能装。

- 安装器点「开始安装」→ 弹出 **VSTOInstaller「Microsoft Office 自定义项安装程序」**，

**安装器做了什么**（源码 `installer/`，.NET 4.7.2 WinForms）：
1. 打开即**自动检测**四项环境，逐项显示 ✓/✗ 与版本号：
   | 检测项 | 检测方式 | 必需性 |
   |---|---|---|
   | Microsoft PowerPoint | 注册表 `App Paths\POWERPNT.EXE` | 必需 |
   | .NET Framework 4.8 | `NDP\v4\Full` 的 Release ≥ 528040 | 必需 |
   | VSTO Runtime 4.0 | `VSTO Runtime Setup\v4R`（x86/x64 视图） | 必需 |

2. **同时检测"是否已安装过"**（读控制面板卸载项）：已装则显示提示并提供「**卸载旧版本**」按钮
   （执行 `VSTOInstaller.exe /Uninstall <已装清单>`，并清理构建期残留的 `|vstolocal` 注册）——
   用于解决"换位置安装时报已安装另一版本"的问题；
3. 缺失项右侧按钮：
   - **下载安装**：打开官方下载页（联网引导）；
   - **安装本地包**：若 `离线安装包\` 内有 `ndp48*.exe` / `vstor*.exe` / `MicrosoftEdgeWebview2Setup.exe`，改为静默安装（请求 UAC）；
4. 装完点「**重新检测**」；
5. 必需项全 ✓ 后「**开始安装**」可用 → 调 `VSTOInstaller /Install` 装 `App\PPTShapeLibrary.vsto`
   （若失败自动回退为"打开 .vsto 走安装向导"），并以"是否真的出现安装记录"判定成功；
6. 底部日志记录每一步。

### 如何测试"缺组件"流程（不用第二台机器）

测完自动**原样还原**（`reg export` 备份 → `reg import` 还原，不动任何文件）。

```powershell

pwsh -File scripts\test-simulate-missing-env.ps1 -Hide -Items both    # VSTO + .NET
# 该窗口会一直等待；测试完成后另开一个普通窗口执行下面这条即可自动还原：
```

**注意事项（都是实测踩到的）**：
- **.NET Framework 4.8 无法隐藏**：`HKLM\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full`
  被系统 ACL 保护，**管理员也删不掉**（这也印证了它在 Win10 1809+/Win11 是 OS 组件，一般电脑必然具备）。
  想验证"缺 .NET"分支只能上老系统或虚拟机。
- **`reg import` 没有 `/reg:32`**：32 位视图的备份必须把 `.reg` 里的路径改写为
  `SOFTWARE\WOW6432Node\…` 再导入，否则会污染 64 位视图且 32 位键回不来。脚本已处理并带还原自校验。
- 安装器的行是**自绘控件**（UIA 里都暴露成 `Pane`、无 `Button` 类型，坐标也不精确），
  用自动化点击容易点错行——脚本化测试建议用"重启安装器 + 读 UIA 文本"而不是坐标点击。
- 离线包按钮点击后会**提权静默安装**（`Verb=runas`），需要真实安装包；用占位文件测会走到
  `OnAction` 的 catch 分支（弹"操作失败"，不会崩）。

### 离线安装包（推荐给他人 / 内网环境）

**最省事的做法：一条命令把三个官方包下到 `dist\离线安装包\`**

```powershell
pwsh -File scripts\fetch-prerequisites.ps1            # 全部
pwsh -File scripts\fetch-prerequisites.ps1 -Only webview2
```

脚本会校验下载物是不是真正的 PE 可执行文件（防止把 HTML 错误页存成 `.exe`），
失败时列出官方页面让你手动补。**打包后的 dist 自带离线包**，别人装的时候按钮直接变「安装本地包」，
完全不联网。这也正是微软 ClickOnce 引导包自己的做法（bootstrapper 里就烤了 `vstor_redist.exe`），
不涉及"重新托管微软二进制"的授权问题。

> ⚠️ **加速站不能直接加速微软的下载**：加速站只代理 `github.com` 域名，
> `download.microsoft.com` 走不了它（实测微软官方源在国内基本打不开）。
> 解决办法是**把官方安装包托管到本仓库的固定 tag**，再用加速站拉——见下节。
> 托管的是**微软签名**的官方文件（VSTO 取自 Visual Studio 的 ClickOnce 引导包），
> 属于"随应用分发依赖"，而非改动或重新打包微软二进制。

### 托管在 GitHub 上的依赖包（国内网络必备）

微软官方源在国内基本打不开，所以官方安装包**同时托管到本仓库的固定 tag `prerequisites`**，
地址永远不变，可配合加速站使用：

```

```

| 资产 | 内容 | 备注 |
|---|---|---|
| `vstor_runtime.zip` | `install.exe` + `vstor40_x64.MSI/CAB`（微软签名的 VSTO Runtime 官方负载） | **已上传**，安装器与取包脚本都优先用它 |

1. 固定 tag 上的资产 → 直连失败自动回退加速站（`ghproxy.net` → `gh-proxy.com` → `ghfast.top`）

## 四点五、自动更新（安装器内置）

仓库：<https://github.com/leobba/PPTShapeLibrary>（**公开**仓库，否则更新检查拿不到清单）

- 打开安装器时会**自动检查**（24 小时缓存，**只被动提示**，不弹窗打断）
- 底部「**检查更新**」按钮：手动重查并弹下载确认 → 下载 → 校验 SHA256 → 解压 → 启动新版安装器
- 清单走**固定地址** `https://github.com/leobba/PPTShapeLibrary/releases/latest/download/update.json`
  （不经 API：匿名 API 每 IP 每小时仅 60 次，**实测被限流 403**）
- 下载直连优先，失败回退加速站；**实测本机 `github.com` 会间歇性被墙**，此时靠加速站成功
- 命令行（可做定时任务 / 无人值守验证）：
  `安装 PPTShapeLibrary.exe --check-update [--download] [--apply] [--out 报告文件]`，
  退出码 0=已最新 / 1=失败 / 2=有新版

发版（维护者）：`pwsh -File scripts\publish-release.ps1 -Version 1.0.3.0 -Notes "改动…"`

> **维护者必读的三个坑**（都实测踩过，脚本已加固但仍需知道）：
> 1. **不要删掉带 Release 的 tag 再重建**：GitHub 会把该 Release 转成**草稿**，而
>    `releases/latest` 会排除草稿 → 线上更新**静默失效**（本项目就是这么踩到的，事后取消草稿才恢复）。
> 2. **按 tag 查 Release 要重试**：网络抖动时返回 404，若当成"不存在"就会创建**同 tag 的重复 Release**，
>    而 `releases/latest` 可能指到缺资产的副本上。
> 3. **PowerShell here-string 里反引号是转义符**：`` `r `` 会变回车，把 "releases" 吃成 "eleases"；
>    含反引号/英文的正文请用单引号 here-string（`@'…'@`）。

### 依赖包安装的两个坑（实测）

1. **`vstor_runtime.zip` 里的 `install.exe` 要用 `/q`，不能用 `/quiet /norestart`**。
   后者是**官方 `vstor_redist.exe`** 的参数；混用会得到 **退出码 4096（=0x1000，参数无效）**——
   进程"正常退出"但**什么都没装**，最容易误判为成功。
   安装器现在按包的形态取参数（`PrereqAsset.Args`），并对非 0 退出码给出提示。
2. **卸载 VSTO Runtime 会连带注销已装的 VSTO 插件**（实测：卸载 VSTO 后，插件的加载项注册与
   控制面板卸载项**都消失了**）。所以"卸载 VSTO → 重装 VSTO"之后，**必须再装一次插件**
   （安装器「开始安装」，或 `VSTOInstaller.exe /Install <…vsto>`）。

安装器装完依赖包后会**自动重新检测**并把结论弹出来（不再要求你手动点「重新检测」）。

## 五、卸载

**推荐：控制面板 → 程序和功能 → `PPTShapeLibrary` → 卸载。**
它执行的就是安装时写入的卸载命令（`VSTOInstaller.exe /Uninstall <清单 URL>`）。

> ⚠️ 手动执行该命令时注意：UninstallString 里的路径**含空格且不带引号**
> （`c:\Program Files\Common Files\Microsoft Shared\VSTO\10.0\VSTOInstaller.exe /Uninstall …`），
> 按空格切分会得到 `c:\Program` 而报"找不到文件"。要在 **`.exe` 处切分**（安装器的 `RunCommandLine` 就是这么做的）。

**卸载后应当干净（2026-10 实测，逐项核查通过）**：

| 检查项 | 期望 |
|---|---|
| `HKCU\Software\Microsoft\Office\PowerPoint\Addins\PPTShapeLibrary` | 不存在 |
| `HKCU\Software\Microsoft\Office\16.0\PowerPoint\Addins\PPTShapeLibrary` | 不存在 |
| `HKCU\…\16.0\PowerPoint\AddinsData\PPTShapeLibrary` | 不存在 |
| 控制面板卸载项 `PPTShapeLibrary` | 不存在 |
| `%LOCALAPPDATA%\Apps\2.0\…` 下的 ClickOnce 应用目录 | 不存在 |
| **`%APPDATA%\PPTShapeLibrary`（素材库数据/设置/备份/日志）** | **保留**（卸载不删数据） |

功能验证：卸载后启动 PowerPoint，功能区**没有**「素材库」，且 `app.log` 无新增行（插件代码完全没跑）。

> 开发版注册的注销走另一条命令：`pwsh -File scripts\dev-register.ps1 -Unregister`
> （它会一并清掉 AddinsData 缓存与**指向本仓库的** VSTO 信任项；不会碰其它插件，例如方方格子）。

## 七、更新版本
1. 修改 `PPTShapeLibrary/PPTShapeLibrary.csproj` 的 `<ApplicationVersion>`（如 1.0.1.0 → 1.0.2.0）；
2. 重新发布：
   ```powershell
   & "C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe" `
     "E:\code\PPTShapeLibrary\PPTShapeLibrary\PPTShapeLibrary.csproj" /t:Publish /p:Configuration=Release `
     /p:ApplicationVersion=1.0.2.0 /p:IsWebBootstrapper=true `
     "/p:GenerateBootstrapperSdkPath=C:\Program Files (x86)\Microsoft SDKs\ClickOnce Bootstrapper\" /nologo /v:m
   ```
3. 产物在 `PPTShapeLibrary\bin\Release\app.publish\`，复制到 `publish\`（保持 `InstallUrl` 一致）；
4. 用户端下次启动插件时会提示更新（或重新运行 setup.exe 覆盖安装）。

> 注意：`PublishUrl/InstallUrl` 在本地测试时用 `file:///…/publish/`；若要"从网络更新"，需把 publish 内容放到 HTTP/UNC 位置并重新发布。当前本地部署不含绝对 URL，不受影响。

## 八、开发版 vs 正式版
| | 开发版（F5 / vstolocal） | 正式版（本说明） |
|---|---|---|
| 注册方式 | `HKCU\…\Addins\PPTShapeLibrary` 指向 `bin\Debug\PPTShapeLibrary.vsto\|vstolocal` | ClickOnce 安装到 `%LOCALAPPDATA%\Apps\2.0` 并注册 |
| 文件来源 | 直接读仓库 `bin\Debug`（改代码即时生效） | 读 ClickOnce 缓存（安装包快照） |
| 卸载 | 删除该注册表项（关闭 PowerPoint 后） | 控制面板卸载 |
| 并存 | 两者**不能并存**：正式版安装后会覆盖同一个注册表键；开发调试前建议先卸载正式版 |

## 九、常见问题
| 现象 | 处理 |
|---|---|
| PowerPoint 里没有「素材库」选项卡 | ① 确认已装 VSTO Runtime；② 文件 → 选项 → 加载项 → 管理"COM 加载项"里勾选 PPTShapeLibrary；③ 重启 PowerPoint |
| 面板空白 / 提示缺少 WebView2 | 安装 Microsoft Edge WebView2 Runtime |
| 安装时提示"未知发布者" | 临时证书签名所致，点继续即可；对外发布建议购买/生成正式代码签名证书 |
| **安装报 `AddInAlreadyInstalledException`（"已安装另一版本的自定义项，不能从该位置升级"）** | 原因：本机已装过一份、且这次从**不同位置**安装（ClickOnce 不允许换位置升级）。解决：安装器上点「**卸载旧版本**」按钮（会自动执行卸载并清理开发式注册残留），或到 控制面板 → 程序和功能 → 卸载 `PPTShapeLibrary`，然后重新点「开始安装」 |
| **不要双击 `bin\Release\PPTShapeLibrary.vsto`** | 那是**构建产物**：直接运行会把它注册成开发式加载项（`…|vstolocal`），与安装器装的正式版抢注册表，并导致后续安装报"已安装另一版本"。安装**只用** `dist\安装 PPTShapeLibrary.exe`（dist 里没有 setup.exe，只有 `App\PPTShapeLibrary.vsto` + `Application Files\`）。已经误注册时：安装器「卸载旧版本」会自动清理，或手动删除 `HKCU\Software\Microsoft\Office\PowerPoint\Addins\PPTShapeLibrary` |
| 素材库数据在哪 | `%APPDATA%\PPTShapeLibrary\`（items 素材、backups 自动备份、logs 日志、settings.json、toolprefs.json） |
| 卸载后想保留数据 | 不要删除 `%APPDATA%\PPTShapeLibrary` |
