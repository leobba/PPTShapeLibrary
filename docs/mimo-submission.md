# 项目说明：从「PPT 素材库插件」到「用 AI 直接在 PowerPoint 里画 PPT」

## 一、做了什么 / 想做什么

**已用 AI 做过的项目：PPTShapeLibrary —— PowerPoint 素材库与 PPT 工具插件（VSTO）**

我长期被两个痛点困扰：一是做 PPT 时反复从零画形状、调样式，收藏过的好看设计无法复用；二是写完一稿后「换字体、统一尺寸、找素材、导出 PDF」全是重复劳动。于是我带着 AI 从零做了一个运行在 PowerPoint 里的「个人素材库」插件，对标 Canva / 创客贴的素材库体验，但素材库就长在 PPT 侧边，随开随用：

- **收藏与插入**：选中形状 / 整页 / 整稿 / 剪贴板都能一键收藏入库；收藏后点卡片即可插入，自动居中、超大自动缩放、插入后自动选中，还带「旋转 / 透明度 / 八向微调 / 撤销」的快速调整条。
- **高保真还原**：渐变、圆角、阴影、三维、发光、文字、旋转等属性完整收藏并还原，收藏的不是「一张截图」，而是「随时能再编辑的真实对象」。
- **素材管理与分享**：双级分类 + 搜索 + 最近使用 + 回收站 + 去重清理；可把收藏导出为素材包（.ppack.zip，含作者署名与 CC BY 4.0 许可元数据）与别人点对点分享、备份迁移。
- **PPT 工具套件**：批量改文字样式、一键换字体、跨页查找替换、文字清理、整稿导出 PNG / 导出 PDF、清理瘦身、统一尺寸、多图网格排版。
- **学术模板**：一键插入开题 / 答辩 / 组会汇报的成套结构页（封面→目录→内容→结论），加页脚页码，4 套预设配色美化图表。

技术形态：C# / .NET Framework 4.8 + VSTO + PowerPoint COM 作为宿主与业务层，界面用 WebView2 承载一套 Vite + React + TypeScript + Tailwind v4 + shadcn/ui 前端，C# 与 JS 通过消息桥协议通信，界面为浅色主题（深色模式已在迭代中移除）。整个项目在多轮高频迭代中完成（仓库现有 120+ 次提交、分批推进），绝大多数代码由我和 AI 编码智能体结对产出。

**最想用 MiMo Desktop 完成的项目：让 AI 真正「替我绘制 PPT」**

现在主流的「AI 生成 PPT」本质是网页模板套内容：只能在线预览、换个字体就乱版、导出后是图片堆叠、无法精细微调——对开题、答辩这类「每个像素都得自己说了算」的场景并不合格。我想在 MiMo Desktop 上做一条真正的闭环：

1. 我把一份提纲、一段文字、一篇论文或一份旧 PPT 丢给 MiMo Desktop，说「帮我做成开题汇报」；
2. MiMo 端侧理解内容结构，按学术 / 商务 / 课程等场景套用设计系统（版式、配色层级、字体、图表规范）；
3. MiMo Desktop 不靠「AI 盲点鼠标」，而是生成结构化的「绘制方案」，由本地执行器（PowerPoint COM / 我的插件工具链）把每一页画成**原生、可编辑的真实形状对象**：封面、目录、章节页、图表、结论页；
4. 画完我直接在 PowerPoint 里点选、改字、换图、微调版式——所有内容可二次编辑，而不是一张「死图」。

更进一步：把 PPTShapeLibrary 沉淀的素材包（.ppack.zip）变成 MiMo 的「设计弹药库」，让 AI 画出来的页面复用我收藏的风格，做到「AI 画的 = 我自己的审美」。

## 二、遇到的问题

**做素材库插件时踩过的坑（也是 AI 协作最有价值的地方）：**

1. **Office COM 对象模型「看似简单、处处是坑」**：想收藏并还原样式，直接读属性再回写会遇到枚举、单位、缺省语义的巨大差异，早期 AI 生成的代码能编译、跑起来却「没效果」。后来改成「复制 → 粘贴 → 归一化 → 从库文稿导出」的思路，用剪贴板搬运真实对象而不是程序化重建样式，还原度问题才彻底解决。
2. **预览图 ≠ 真实效果**：从源页面固定画布导出的缩略图会文字错位、形状越界，后来改为先归一化再按自然尺寸导出，才做到「所见即所得」。
3. **WebView2 与 VSTO 桥接的异步与超时**：首次插入时 COM 冷启动可能超过 8 秒，前端误报失败、用户重复点击导致重复插入——靠加长超时、插入防连点、慢操作日志逐一定位。
4. **进程内难复现的 COM 崩溃**：很多问题只能靠实机反馈，于是把「分批小步提交 + 日志 + 产物自检（smoke）」固化成流程，AI 每次改动都可回滚、可定位；Ribbon 自绘图标在实机上消失过一次，也靠回滚到稳定实现解决。
5. **两套 UI 并存期的口径混乱**：界面从 WPF 面板迁移到 WebView2 Web UI，期间新老前端、业务层、桥协议三处语义不一致，最终统一为「C# 只做业务、JS 只做界面、桥只做翻译」的清晰分层，旧 WPF 面板整体退役。

**做「AI 绘制 PPT」预期会遇到的问题：**

- 通用模型会「想内容」但不擅长「排版」——字号层级、留白、对齐、配色对比度这类规则性知识，靠对话式 prompt 说不清，必须把设计规则程序化、可复现，并自动校验；
- 桌面自动化环境复杂（Office 版本、DPI、窗口状态差异），所以方案是「AI 规划 + 生成结构化绘制指令，本地执行器落地」，而不是让 AI 直接操作鼠标；
- 答辩材料常涉隐私、不便上传云端，希望理解与生成尽量在 MiMo Desktop 本地完成。

## 三、用了哪些工具

- **AI 辅助**：以编码智能体结对开发（可替换为你实际使用的工具名）+ MiMo Desktop（规划中的绘制工作流入口）
- **宿主与语言**：Visual Studio 2022、C# / .NET Framework 4.8、VSTO、PowerPoint COM（Microsoft.Office.Interop.PowerPoint）
- **界面宿主**：WebView2（Edge Runtime）
- **前端**：Vite + React + TypeScript + Tailwind CSS v4 + shadcn/ui（lucide 图标）
- **工程与协作**：Git（120+ 提交分批迭代）、PowerPoint 2016+ / M365 x64 实机验证
- **规范与测试**：素材包格式规范文档、产物完整性自检脚本（smoke）、开发测试清单
